SECTION 1 — WHAT IS THIS PROJECT?
================================================================================

Project Name: SYNTHÉ (also written "Scynthé" in some places)
Live URL: https://synthe-nu.vercel.app
GitHub Branch: main → auto-deploys to Vercel

SYNTHÉ is a full-stack web platform for 3D designers, AR/VR developers, and
AutoCAD engineers. It acts as:
  - A marketplace where creators upload, sell, and showcase 3D/AR/VR work
  - A social/professional network for XR (Extended Reality) developers
  - A project collaboration hub (post & take requests)
  - An admin-controlled certification/verification system

Target Users:
  - 3D artists & modellers (upload GLB, GLTF, OBJ, FBX models)
  - AR/VR developers (upload Unity/Unreal ZIP builds)
  - AutoCAD engineers (upload DWG, DXF blueprints)
  - Clients who want to hire or commission XR work
  - PIET (academic institution) students & collaborators

SECTION 7 — KEY FEATURES IN DETAIL
================================================================================

--- 7.1 UPLOAD SYSTEM ---
Route: /upload
Supported formats:
  - 3D Models: GLB, GLTF, OBJ, FBX, DWG, DXF (up to 500MB)
  - AR/VR Builds: ZIP package (up to 2GB)
Storage flow:
  1. File → Supabase Storage, bucket "models" (public)
  2. Thumbnail image → Supabase Storage, bucket "thumbnails" (public)
  3. Metadata → Firestore "models" collection
Monetization: Free OR paid listing. If paid, Razorpay handles purchase.

--- 7.2 GALLERY & 3D VIEWER ---
Route: /gallery
  - Tab filter: 3D Models | AR Builds | VR Builds
  - Search by name, filter by type/genre/price
Route: /gallery/[modelId]
  - In-browser 3D viewer using Three.js (app/components/Viewer.tsx)
  - Supports GLB, GLTF, OBJ formats
  - Comments system (Firestore)
  - Like (toggle), views counter, download counter
  - Paid model: gated via Razorpay → /api/create-order → /api/verify-payment

--- 7.3 DEVELOPER CONNECT ---
Route: /connect
  - Browse developers (filter by skills/certification)
  - DeveloperCard.tsx shows name, bio, skills, rating, hire/chat buttons
Route: /connect/chat
  - Direct messaging (Firestore real-time)
Route: /hire
  - Book 1-on-1 mentorship/tutoring sessions
Route: /requests/open
  - Public board of project requests from clients
Route: /requests/post
  - Authenticated users can post project requests

--- 7.4 PAYMENTS ---
Flow:
  1. User clicks "Buy" on paid model
  2. Frontend calls POST /api/create-order (creates Razorpay order)
  3. Razorpay checkout opens in browser
  4. On success, frontend calls POST /api/verify-payment (verifies HMAC signature)
  5. If verified → write to Firestore "purchases" → grant download access
Fee structure: 15% platform fee + ~2% Razorpay processing fee

--- 7.5 AUTHENTICATION ---
Firebase Auth with:
  - Email + Password
  - Google OAuth Sign-In
After sign-up: user doc created in Firestore "users" with role = "user"
Roles: user | developer | admin
Role stored in Firestore, checked via lib/checkAccess.ts and middleware

--- 7.6 ADMIN PANEL ---
Route: /dashboard/admin (role = admin only)
Features:
  - View/delete any model
  - Change user roles (promote to developer/admin)
  - Approve/reject developer applications
  - Approve/reject certification requests
  - View platform stats (AdminAnalytics.tsx + Recharts)

--- 7.7 AUTOCAD HUB ---
Route: /autocad
  - Separate gallery for DWG/DXF blueprints
  - Similar structure to main gallery

--- 7.8 COLLABORATORS / PIET ---
Route: /collaborators
  - Showcases PIET (academic institution) student/faculty collaborators
  - Academic partnership section

--- 7.9 CERTIFICATION ---
Route: /certification
  - Developers can apply for a "Verified" badge
  - Requests go to Firestore "certificationRequests"
  - Admin approves → updates user doc field: isCertified = true

--- 7.10 REAL-TIME PROJECT CHAT ---
Route: /project-chat/[chatId]
  - Firestore onSnapshot listener for real-time messages
  - Used for project negotiation between client and developer

SECTION 9 — KNOWN ISSUES & NOTES (as of March 2026)
================================================================================

1. SUPABASE ANON KEY FORMAT
   The Supabase anon key must be a JWT (starts with "eyJ...").
   The new "sb_publishable_..." format does NOT work for file uploads.
   Fix: Go to Supabase Dashboard → Settings → API → copy "anon public" JWT key
   → update .env.local AND Vercel environment variables → redeploy.

2. VERCEL DEPLOYMENT
   Hobby plan: only one deployment at a time.
   If a deployment gets stuck on "Initializing", cancel it in:
   Vercel Dashboard → Deployments → Cancel → then trigger a new commit/deploy.

3. DOWNLOAD URLS
   Models uploaded to Supabase have public URLs.
   Older models may have Cloudinary URLs (legacy).
   The download button in gallery/[modelId]/page.tsx handles both URL formats.

4. PROJECT NAME INCONSISTENCY
   - package.json: "zenith" (old name)
   - Displayed name: "SCYNTHÉ" or "SYNTHÉ"
   - layout.tsx title: "Scynthé"
   These are all the same project — naming evolved during development.

5. FIREBASE STORAGE vs SUPABASE
   Firebase Storage is initialized in lib/firebase.ts but NOT used for models.
   All model/thumbnail storage is on Supabase.
   Firebase Storage may be unused legacy code.
